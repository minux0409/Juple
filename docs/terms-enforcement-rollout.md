# 강제 동의 OFF의 화면 호환성과 연령 미지원 클라이언트

기준 HEAD: `0b884ffbcdf795abb4fe94145a7d8a4f3e5be222`. 구현 및 관련 자동 테스트 완료 / 미커밋 / PROD 미적용.

## 정책 값과 동의 사실의 분리

사용자 요청의 RequireTermsAcceptance는 기존 서버의 `Terms:EnforceAcceptance` 정책을 뜻한다. 새 설정을 만들거나 기존 설정을 바꾸지 않았다.

`GET /api/v1/users/me/terms`, 동의 성공 응답, bootstrap의 terms 객체에 `enforceAcceptance`를 추가했다. 값은 기존 TermsOptions에서 가져오며 `isAccepted`, `acceptedVersion`, 동의 시각과 독립적이다. OFF라고 사용자를 동의 완료로 저장하거나 표시하지 않는다. 구형 클라이언트는 추가 필드를 무시한다.

새 Web의 자동 화면 제한은 `enforceAcceptance && !isAccepted`일 때만 적용된다. OFF인 한국어·비한국어 미동의 사용자 모두 홈과 기존 일반 화면으로 진입한다. 일반 API의 인증·소유권·쓰기·구독 권한 검사는 변경하지 않았다. 신규 구매 및 토큰 연결 복원에 대한 기존 개별 동의 제한도 유지한다.

## 수동 동의와 개별 요청 거절

- 고객센터의 기존 이용약관/개인정보 링크를 보존하고 수동 약관 동의 진입을 추가했다.
- OFF의 수동 동의 화면은 닫고 돌아갈 수 있다. 닫기는 동의 상태를 변경하지 않는다.
- ON이고 현재 약관에 미동의한 경우 닫기 동작을 제공하지 않는다. 승인된 본문·언어와 필수 체크가 모두 준비돼야 동의할 수 있다.
- 승인되지 않은 언어의 canAccept=false는 유지한다. OFF의 홈 진입 허용은 번역 승인이나 한국어 대체 동의 승인이 아니다.
- 구매 등 개별 요청의 termsAcceptanceRequired(403)를 전체 강제 동의 ON으로 해석하지 않는다. 원래 요청은 거절한 채 수동 화면을 열고 서버 상태를 다시 조회한다. 응답의 실제 enforcement 값에 따라 필수/선택 모드를 결정한다. 원래 구매·쓰기 요청을 자동 재실행하지 않는다.
- 세션 종료나 API 교체 후 도착한 오래된 상태 조회가 다른 세션에 적용되지 않도록 요청 세대를 무효화한다. 구독 만료 거절을 약관 거절로 바꾸지 않는다.

서버 필드가 없거나 잘못된 타입이면 Web은 보수적으로 강제 동의가 켜진 것으로 해석한다. 따라서 새 API를 먼저 배포해야 OFF 정책이 정확히 전달된다.

## 연령 미지원 앱과 업데이트 안내

연령 확인을 보내지 않거나 false를 보낸 요청은 기존대로 400 minimumAgeConfirmationRequired다. 자동 true 처리·자동 동의·과거 기록 보정은 없다. Android 42/iOS 11의 version·isAtLeast14 요청 형식은 기존 2026-10-14 호환 경로로 정상 처리된다.

연령 확인 거절이 발생해도 OFF인 서버의 일반 GET/POST 약관 필터는 새로 켜지지 않는다. Web은 실제 동의 여부를 그대로 보관한 채 일반 화면을 사용할 수 있다. 그러나 **이미 설치된 오래된 Native 바이너리 자체가 동의 화면으로 강제 이동하는 경우, 서버의 새 필드만으로 그 화면 코드를 바꿀 수는 없다.** 동의가 필요한 상황에서는 연령 지원 앱으로 업데이트해야 한다.

- 기존 앱 시작 시 공개 최신 버전 정책을 확인하는 업데이트 안내는 그대로 유지한다. 더 오래된 앱에서는 이 경로 또는 스토어 자체에서 수동 업데이트한다.
- 새 소스의 TermsUnavailable 화면에 수동 업데이트 버튼을 추가했다. 기존 공개 업데이트 정책·설치 앱의 bundleId·기존 openStore 도우미를 이용한다. 스토어 열기 실패는 안내하고 재시도할 수 있다.
- 업데이트 버튼을 누르기 전에는 스토어 조회/이동을 실행하지 않는다. 이를 눌러도 동의 제출·연령 확인·구독 구매를 실행하지 않는다.
- 이 새 버튼이 현재 배포된 구형 바이너리에 소급 추가되는 것은 아니다. 이 Native 변경의 실제 기기·스토어 이동은 이번에 검증하지 않았다.
- Android 최소 24/iOS 최소 1, 기존 최신 버전 정책 및 빌드 번호는 변경하지 않았다. 모든 과거 바이너리의 신규 동의가 보장된다는 뜻은 아니다.

## 배포 판단과 순서

Web 비한국어 사용자 차단은 OFF 조건에서 코드상 해결했다. 기존 Android 42/iOS 11 요청도 유지된다. **이 범위의 API → Web 배포 준비는 가능하나, 모든 구형 설치 앱의 신규 동의 무중단을 보장하는 판정은 아니다.** 연령 미지원 앱은 수동 업데이트 전 동의할 수 없으며, 해당 사용자의 최신 앱 설치 가능 여부와 운영 전환 범위는 배포 승인 전에 확인해야 한다. 최신 앱을 설치할 수 없는 사용자까지 정상 신규 동의를 보장해야 한다면 현재 제약만으로는 배포 승인 조건이 충족되지 않는다.

별도 Commit/Push 및 PROD 승인 후 제안하는 순서:

1. 현재 약관 버전·enforcement OFF·ProgramEnabled=false·최소 지원 버전을 유지한 채 새 API만 배포하고 건강 상태 및 읽기 전용 상태 응답의 enforceAcceptance=false를 확인한다.
2. API 정상일 때만 Web 배포. 미동의 비한국어 홈 진입, 수동 동의 열람/닫기, 기존 로그인·조회·구독 관리 경로를 확인한다. 실제 동의 제출/구매/무료 체험 지급은 별도 승인 없이는 실행하지 않는다.
3. 장애 시 Web부터 이전 이미지로 복귀한 뒤 필요하면 API를 복귀한다. 새 Web을 남기고 필드가 없는 이전 API부터 복귀하면 보수적 기본값 때문에 OFF 사용자의 자동 화면 제한이 재발할 수 있다.

이번 작업에서는 위 배포를 실행하지 않았다. 기존 동의 버전·시행일·강제 동의·ProgramEnabled·최소 지원 버전과 실제 사용자 기록을 변경하지 않았고, 미승인 약관을 공개 경로에 연결하지 않았다. 마이그레이션·패키지 추가 없음. Commit/Push도 별도 승인 대기다.
